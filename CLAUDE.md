# CLAUDE.md

Optimistic-style ETH bridge: Solidity (Foundry) in `contracts/` and Java 25 services (Maven multi-module) in `services/`. Takes precedence over the parent folder `CLAUDE.md`.

## Commands

```bash
scripts/install-deps.sh                          # forge-std + OpenZeppelin v5.4.0 into contracts/lib (not committed)
cd contracts && forge test                       # 121 tests; FOUNDRY_PROFILE=ci for the exhaustive run
cd contracts && forge fmt --check
cd contracts && forge coverage --no-match-coverage "script|test" --report summary   # must stay at 100 % of src/
cd contracts && forge snapshot --check           # run `forge snapshot` after intentional gas changes
cd contracts && forge script script/GenerateTreeVectors.s.sol --tc GenerateTreeVectors   # rewrites ../testdata/tree-vectors.json
source /c/Users/srg/tools/env.sh && ./mvnw -T 1 verify    # JDK 25 + Maven wrapper; needs anvil and forge on the PATH
scripts/demo.sh                                  # KEEP=1 to leave it running; ports 18545/19545/18088 (override with L1_PORT, L2_PORT, STATUS_PORT)
```

## Architecture

- `contracts/src/{l1,l2,lib,interfaces}`: `L1Bridge`, `OutputOracle`, `L2Bridge`, `BridgedETH`, `IncrementalMerkleTree`, `Withdrawals`. Behaviour is described in `docs/SPEC.md`.
- `services/core` has NO I/O dependencies (ports, models, tree, ABI codec, Keccak, sealed state machines, in-memory store). `adapters` implements the ports (JSON-RPC, web3j-crypto signing, SQLite). `services` has the use cases and depends on ports only. `testkit` starts native Anvils and deploys the real build artifacts. `app` is the CLI. `e2e` holds the scenario tests.
- `testdata/tree-vectors.json` is generated by Solidity and read by the Java core tests. Never edit it by hand; regenerate it.

## Conventions

- Tests are named `test_`, `test_RevertWhen_`, `testFuzz_`, `invariant_` (Solidity); Java scenario tests are named after the plan IDs (`e1_`, `e3_`, ...).
- Services must stay idempotent: reconcile with the chain first, then act; persist intent before an external side effect.
- Keep the ports small; do not let `core` depend on Jackson, web3j or JDBC.
- Never describe this as audited. Slither runs only in CI (no Python locally); its inline silences carry their reason, keep it that way.
- Test keys only (public Anvil accounts). Real keys never enter the repo. `.env` is ignored.
- Do not use the Windows Store `python`/`python3` stubs here: they hang.
- No commit or push without the owner's approval. No `Co-Authored-By` lines.
- Demo ports default to 18545/19545/18088 and overlap with the `go-mini-rollup` demo (18545/19545/19546): run one at a time or override with `L1_PORT`/`L2_PORT`/`STATUS_PORT`. Never `taskkill /IM anvil.exe`: kill by PID.
